# 保理直联分析：字段映射与人工稿对齐

## 适用范围

仅用于保理银企直联分析（含该场景的银行接口与平台标准接口字段映射，以及这些分析文档的增量更新）。普通保理 PRD、页面设计、其他融资模块及其他业务接口分析不因涉及“保理”或“接口”而使用本参考。不将这里的工作簿结构、映射决定或场景码推广为通用 PRD 规则。

依据：2026-11-06 本次《交通银行直联分析》人工稿及随后用户明确修正；2026-11-26 用户要求写入 skill，并限定仅在保理直联分析时使用。样例中的银行字段、金额与主体映射仍需按具体项目核对。

## 1. 先确定标准对象，再映射字段

本项目已明确：**融资状态推送、融资结果查询、还款结果查询的结果字段，均对应“平台侧融资保理结果查询标准响应” `FactoringFinancingResultResponse`。**

| 内容 | 对应标准对象 |
| --- | --- |
| 融资申请请求 | `FactoringFinancingApplyRequest` |
| 融资申请同步应答 | `FactoringFinancingApplyResponse` |
| 融资结果查询、还款结果查询的请求参数 | `FactoringFinancingResultRequest` |
| 融资状态推送的业务结果、融资结果查询响应、还款结果查询响应 | `FactoringFinancingResultResponse` |

- 银行推送在银行接口中标为“请求”，不代表应映射平台标准申请请求；按银行→平台→业务端的业务数据流确定目标对象。不要因接口名或 HTTP 请求/响应方向选错标准结构。
- 保留研发设计的真实中英文字段。结果映射中不能直接使用仅在申请请求定义的 `finOrgSocialCreditCode`、`应付单信息.accountsPayNum`；这些信息可用于核对或查找原单，写在取值逻辑中。经原单关联回填 `askNumber`、`finBizDocCode` 时，说明关联关系。
- 本项目融资结果使用 `financingScene=LOAN`，还款结果使用 `financingScene=REPAY`。先核对场景下的业务含义，再判断同一个响应字段能否复用；不只凭英文名判断字段专属于某场景，也不因共用响应就混淆还款总额、还本金额和实还利息。
- 标准字段存在性、业务含义和取数关系分别检查。标准没有定义、关联依据不足或枚举未明确时，不造英文名、不强配、不把分析建议写成已确认规则。其他项目使用其当前已批准的标准结构，不机械照搬本项目类名和码值。

## 2. 分析逻辑：围绕本次业务取数

此前问题是把映射表写成了逐字段审查说明：每行填充“标准缺项”“不可替代”“待确认”，却弱化了具体取数与本期范围。调整为：

- 明确同义字段直接填写标准英文、中文；只有汇总、默认、转换、关联、条件或结果更新需要说明时，才填写处理逻辑。
- 无已确认映射的单元格可以留空。**空白不等于不传、不适用或银行非必填**；仍保留银行原始必输、类型、长度和备注，并识别会阻断本次对接的缺口。
- 人工稿的主体、金额、日期及默认值修订，按具体业务决定处理，不能只当成文字精简。例：本次人工稿将借款人信息改取应付单付方、债权凭证类型默认0；这不是其他银行或所有保理场景的默认规则。共用字段需检查本次其他接口的实际影响，不将申请取数直接扩展成响应字段。
- 区分银行直接返回、平台按原单关联回填、平台计算和当前未定义的数据；标准响应没有直接返回的字段，不代表可以虚构银行值，也不必一律新增标准字段。只有标准与业务语义确认后才复用或提出扩展。

## 3. 文字与文档结构：以最新人工稿为准

- 同义关系用映射列表达，不重复写“取对应字段”。处理逻辑沿用“发票金额汇总计算”“取应付单付方账号户名”等短句，不在每行重复解释未选方案。
- 本次人工样例为12列：银行原文8列，后接“标准分组、标准英文字段、标准中文字段、取值逻辑/转换及处理”。沿用该样例时，不补回已删除的“标准接口/对象、映射结论、来源”列。其他已有列结构按当前人工稿保留，不强制改为12列。
- 用户收敛为“接口对接范围＋各接口”后，不自行恢复长总览、覆盖检查或状态说明工作表。核对过程可以保留为内部工作记录，不自动变成用户交付页面。
- 未定规则按用户当前结构组织；用户已移除集中待确认页时，只在必要的对应字段简短注明，不为执行通用模板而恢复页面。留空不掩盖影响对接的关键未知项。
- 人工申请页移除通用应答行，不代表其他接口都删除响应。查询和推送所需的融资、还款业务结果继续保留；增量修改保留银行原文和未受影响的人工内容。

## 4. 保存前后的针对性检查

- 写前确认当前工作表、列和人工修改，旧快照仅作比较，不恢复用户已删除的内容。对照时区分风格偏差、先前映射错误、用户新决定及仍未定事项。
- 每个结果区的标准英文字段均属于本次选定的 `FactoringFinancingResultResponse`；请求区另按其请求标准检查。字段存在性通过不代表语义正确，仍核对场景、主体、金额、状态和关联关系。
- 仅修改受影响的映射与处理列；回读核对银行原文、人工稿保留、更新字段及旧说明清除结果。用户同时继续编辑时，保留其新内容，不回滚成旧基线，也不把并行人工变更误报为自身改写。
